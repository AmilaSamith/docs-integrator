- To host the docs site on localhost, run `npm install` once in `en`, then run `npm run start -- --host localhost` from `en` and open the localhost URL printed by Docusaurus.

## Before touching `en/docs/`

Read [CONTRIBUTING.md](CONTRIBUTING.md) first — in particular "Golden
Rules" and "Doc structure conventions". The short version, as a
pre-flight checklist for any change that adds, moves, or renames a doc:

- [ ] **Not editing synced content on `saas`.** `platform-overview/`,
      `editor/`, `develop-and-test/`, `customize/`, `migrate/`,
      `guides/`, and `reference/glossary.md` are synced from
      `wso2-integrator` — a direct edit here gets silently reverted and
      the CI guard (`shared-content-guard.yaml`) rejects the PR. If the
      task touches one of these, the PR belongs on `wso2-integrator`,
      not here — say so rather than making the edit.
- [ ] **New/moved doc has an explicit `slug:`** in frontmatter, matching
      its actual route — never rely on the path-derived default.
- [ ] **New folder with 2+ docs has an index page** at
      `<folder>/<folder>.md` (`sidebar_position: 0`,
      `sidebar_label: Overview`, `slug:` = the folder's own route) —
      otherwise the folder is a dead-end category label in the sidebar.
- [ ] **New folder with 2+ files has an explicit `_category_.json`**
      (`{ "label": "...", "position": N }`), and every doc inside it has
      an explicit `sidebar_position` — don't leave ordering to the
      alphabetical fallback.
- [ ] **Every reference to a moved/renamed path is updated.** `grep` the
      whole repo (`docs/`, `src/`, `docusaurus.config.ts`,
      `sidebars.ts`) for the old path, including `static/img/` paths the
      doc references, before deleting the old file. Relative links
      (`../foo.md`) silently point at the wrong file when nesting depth
      changes, even without a literal broken-link warning.
- [ ] **Verified with a real build, not a visual skim.** Run
      `npx docusaurus build` from `en/` and confirm it doesn't report
      new broken links (a handful of known pre-existing ones show up on
      every page via stale footer/layout links — those aren't yours to
      fix unless asked; anything new pointing at a path you touched is).
- [ ] **Sidebar needs a visual section break?** Use
      `_category_.json`'s `customProps: { "separatorBefore": "Label" }`
      (rendered by `en/src/theme/DocSidebarItems/index.tsx`) — never
      hand-write part of `sidebars.ts` to force an order or grouping;
      that reintroduces the stale-sidebar-entry class of bug the fully
      autogenerated sidebar (`sidebars.ts`'s own doc comment explains
      why) exists to avoid.
